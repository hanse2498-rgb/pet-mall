# 问答助手 · 设计方案（V1）

> 状态：已确认　2026-10-13　顶栏购物车左侧入口，仅限宠物话题的 AI 聊天

## 已确认决策

| 项 | 决策 |
| --- | --- |
| 模型通道 | **本地知识库 + 预留外部 LLM**（`AiService` 抽象，默认本地兜底，配置 key 后走真实模型） |
| 登录 | **必须登录**，历史按用户隔离 |
| 输出 | **SSE 流式**（打字机效果） |

## 入口
顶栏：`… 宠物社区 │ 🛟问答助手 │ 🛒购物车 用户名` → 点击进 `/assistant`

## 页面 `/assistant`
- 气泡消息流（用户右 / 助手左）、输入框 + 发送
- 顶部：会话标题、清空
- 底部：宠物推荐问法快捷词
- 多轮带上下文；未登录 → 引导登录

## 话题约束（核心）
- **系统提示约束**：限定为「宠物领域助手」：养宠/食品/洗护/行为/常见疾病预警/用品选购。
- **范围判定 + 友好拒绝**：非宠物话题 → 一句话礼貌引导回正题，不继续答。

## 后端
- `AiService` 接口 + 实现：
  - `LocalPetAgent`：内置宠物常见问答知识库 + 规则匹配（默认）
  - `OpenAiAgent`（预留）：配置 `ai.provider/openai.key` 后走外部 LLM（OpenAI 兼容 /api），带严格 system prompt + 话题拦截
- 接口 `GET/POST /api/assistant/chat`（ **SSE 流式**，需登录）
- 会话历史存 `tb_chat_message`，支持多轮与按用户查看、清空

## 数据模型
- `tb_chat_message`（id, user_id, role(user/assistant), content, create_time）
- 新增唯一会话？V1 用一个会话流即可；可加 session_id 字段预留多会话

## 安全 / 限流
- 仅宠物话题；限单次长度、按用户频率（复用限流思路）
- basic 长度/内容校验

## 开发步骤
1. 建表 + `AiService` 抽象 + 本地知识库实现 + SSE 接口
2. 顶栏入口 + `/assistant` 路由 + 聊天 UI（气泡/输入/推荐/清空/流式）
3. 话题约束与登录校验；预留外部 LLM 配置位
